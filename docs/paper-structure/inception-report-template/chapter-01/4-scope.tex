\section{Scope of the Project}
\label{sec:intro_scope}

Based on our reading of the literature so far, we intend to bound this project by one governing rule: we plan to work only with attack surfaces for which a dedicated, reusable, oracle-backed benchmark already exists in the surveyed literature, rather than constructing new benchmarks ourselves. This is a scope we have provisionally settled on; it may narrow further once early implementation work tells us more about what is realistically achievable within the remaining timeline. Table~\ref{tab:in-scope-surfaces} summarizes the attack-surface families we are currently considering in scope and the benchmarks that would bound any claim made about them.

\textbf{What we currently intend to leave out.} General REST API exploitation is not something we plan to evaluate directly: RESTler's \citep{atlidakis2019restler} evaluation targets are one-off real-world case studies rather than a standardized, reusable benchmark, so we did not find an equivalent of the other benchmarks above for REST APIs specifically. Some of RESTler's underlying techniques (dependency inference between API calls, response-feedback pruning) may still turn out to be useful internally, e.g. within GraphQL testing, but we do not plan to report REST-specific results. For the same reason -- the absence of a suitable existing benchmark within our survey -- binary exploitation, physical- and network-layer attacks, and social engineering are also outside what we currently intend to attempt.
