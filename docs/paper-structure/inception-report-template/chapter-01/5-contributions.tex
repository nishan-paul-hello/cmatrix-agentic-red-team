\section{Anticipated Contributions}
\label{sec:intro_contributions}

We want to be careful not to overstate what this thesis has established at this point -- none of the following has been implemented or evaluated yet. What follows is the direction we currently believe is worth pursuing, framed as hypotheses to be tested rather than results already in hand. We expect this list to be revised, narrowed, or partly abandoned as our implementation and early experiments give us evidence the literature review alone cannot.

\begin{itemize}
    \item \textbf{Dependency-aware exploration.} Our primary hypothesis is that combining exploration-style candidate selection with an explicit, dynamically-grown model of prerequisite relationships between vulnerabilities -- rather than treating either concern in isolation -- can improve how thoroughly and how sensibly an autonomous agent searches a target. We intend to test this against CVE-Bench and PentestEval once an implementation exists, but we are not yet in a position to state expected numbers with confidence.
    \item \textbf{Reuse of prior experience across missions.} We would like to examine whether allowing an agent to retain and selectively reuse strategies from earlier engagements produces a measurable benefit on targets that share underlying technology, without introducing the negative-transfer risk described in Section~\ref{sec:intro_challenges}. Whether this ends up being a core contribution or supporting infrastructure will depend on what our early ablations show.
    \item \textbf{An honest, cross-benchmark evaluation.} Independently of whether the above hypotheses hold, we intend for the evaluation itself -- run consistently across more than one existing, independently-published benchmark, with standardized oracles and clearly separated per-surface reporting -- to be a useful methodological contribution to how this class of system gets evaluated, since we did not find this done consistently in the papers we surveyed.
\end{itemize}

Several further mechanisms that recur across the surveyed literature -- structured hand-off between agent components, retry-and-diagnose validation loops, and detailed run logging -- currently look like necessary supporting infrastructure for any implementation of the above rather than contributions in themselves. We plan to revisit this framing once implementation is further along.
