\section{Expected Contributions}
\label{sec:intro_contributions}

We want to be careful not to overstate what this thesis has established at this point. None of the following has been implemented or evaluated. What follows is the direction we currently believe is worth investigating, framed as working hypotheses rather than results already in hand. We expect this framing to be revised as implementation and early experiments give us evidence the literature review alone cannot provide.

\begin{itemize}
	\item \textbf{Dependency-aware exploration.} Our primary hypothesis is that combining exploration-style candidate selection with an explicit, dynamically grown model of prerequisite relationships between vulnerabilities --- rather than treating either concern in isolation --- can improve how thoroughly and how sensibly an autonomous agent searches a target. We intend to test this against CVE-Bench and PentestEval once an implementation exists, but we are not yet in a position to state expected performance numbers with confidence.
	\item \textbf{Reuse of prior experience across missions.} We would like to examine whether allowing an agent to retain and selectively reuse strategies from earlier engagements produces a measurable benefit on targets that share underlying technology, without introducing the negative-transfer risk described in Section~\ref{sec:intro_challenges}. Whether this ends up as a core research question or supporting infrastructure will depend on what early design work shows.
	\item \textbf{An evaluation grounded in existing benchmarks.} Independently of whether the above hypotheses hold, we intend for our evaluation to be run consistently across more than one existing, independently published benchmark, with standardised oracles and clearly separated per-surface reporting --- since we did not find this done consistently across the papers we reviewed.
\end{itemize}

Several further mechanisms that recur across the surveyed literature --- structured communication between agent components, retry-and-diagnose validation loops, and detailed logging --- currently appear to be necessary engineering infrastructure for any implementation of the above rather than independent research questions in themselves. We plan to revisit this framing as implementation progresses.
